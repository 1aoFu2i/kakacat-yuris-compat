# 《乐园之扉HD》咔咔喵兼容适配

目标运行环境为咔咔喵（KrkrCat）。本案例包括已核对的原版和高清步兵变体，工具按源文件指纹区分版本。

## 汉化资源加载

该样本的汉化资源位于 `乐园_高清版.exe` 的 MoleBox 封装中。Windows 运行汉化 EXE 时可取得封装内文件，直接将可见资源交给咔咔喵不能保证同样的加载路径。此次采用静态读取：不执行 EXE/DLL，展开 16 份已确认路径资源，验证另外 1 份十字节资源以及全部 1,722 个数据块。

展开后以封装内有效资源替换 `pac/update2.ypf`、`pac/update3.ypf` 的一字节占位文件，保持字体、字幕、应急图片和必要 DLL 的原路径与大小写。`OP.ass` 保留原大小写。原 `update1.ypf` 占位保持。工具不会删除或改写源目录。

原版沿用 39 文件资源组合。高清变体保留自己的 CG、配置和六个当前保存文件，沿用 43 文件组合；不会借用原版 CG 或备用解锁存档。高清源已有的 `yshpd.dat` 与封装内十字节资源一致，按该版本保留；原版保持历史 39 文件基线，报告仅记录该十字节资源的指纹，资源包不包含它。

源目录的保存文件名集合必须匹配所选 profile：原版为三份系统保存文件，高清变体为已核对的六份文件。已有其他个人存档时工具会拒绝；请保留原目录和存档，另准备匹配的干净源副本，不要删除个人存档来满足检查。

## 读档遮挡的证据与 R1

历史取证包中，手机报告黑色对象 `SPL101` 可见、不透明，尺寸为 911×683；遮挡边界与这一数值一致。脚本及故障存档显示，FD 黑层的转场进度已经到透明终点，普通不透明度仍为 256。报告尺寸不是对真实合成层、T/TA 或解释器内部行为的完整测量。

最终 R1 从原始 BN 重建，移除诊断包中的弹窗及其他候选修改，只扩展 `ysbin/yst00026.ybn` 的零基 PC5211 条件：

```text
@2742[@3428] == 0
OR (@3428 == @2956 AND @3451 == 0)
```

保留紧随其后的 PC5212 `A=A*TP/256`。新增条件只让非链接 FD 遮罩在 TP=0 时同步普通不透明度为零；中途转场、其他图层及链接分支保持。追加 57 字节表达式，保留原命令、控制地址、行号、表达式前缀、对象与转场流程。

历史广泛调整和诊断包未形成最终修复；S2 曾在手机启动失败，S3 修正诊断格式后取得了上述观察数据。公开工具直接复现最终 R1，不带入这些诊断包。

用户随后确认 R1“成功解决了”读档持续黑块。这一结果限定于已测场景，完整三轮、全部路线和退出读档清单未逐项确认。

## 全画面转场候选 R2

用户在 R1 成功后仍报告启动和场景切换中闪过局部矩形。共用 `MAC.FOUT` 的中心表达式为 `BASE/2/1.28`，得到 400,300；1024×768 资源的中心为 512,384。偏移与 911×683 静态裁剪模型一致，支持校正请求中心，但尚未直接测量该次手机转场的 MATH3D 投影。

R2 完整保留 R1，缩短 PC2398、PC2399 的 PFLT2 表达式引用，将 `BASE/2/1.28` 改为 `BASE/2`。相对 R1，加密脚本只有偏移 79288、79360 两字节变化（`63→75`）；原表达式内容、淡入淡出时长、图案、等待与清理流程保持。

R2 从原始 BN 一次组合 R1＋R2，不向已扩展的 R1 BN 再追加。先检查 update3 没有覆盖目标 26 号脚本，再写回既有 BN 条目。

## 用法及验收

原版优先用 `euphoria-r1`。`euphoria-r2` 与 `euphoria-alt-r2` 为待手机验收的候选，独立导入并保留成功的 R1 条目。

1. 检查中文菜单、剧情、图片和语音；冷启动至菜单重复三次。
2. 在第一次选择前存读档，作为健康对照。
3. 在第一次选择后的场景切换完成、第二次选择前存读档，先停留数秒，再推进对白和开关菜单。
4. 人物场景、事件 CG 场景分别至少三轮，退出重开后再读档。
5. R2 另检查启动、黑白及到达的图案转场是否完整覆盖画面，原转场时长正常，R1 读档问题无回归。

原版 R2 和高清变体目前均只有文件级验证。未到达的后续场景记为未覆盖；若仍异常，记录准确阶段及出现/消失操作，不自动叠加其他猜测修改。
