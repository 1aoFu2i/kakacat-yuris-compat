# 咔咔喵兼容工具的验证与复现

工具仅处理支持配置中已核对的源版本。关键 EXE 和 YPF 哈希不匹配时停止；不会因为名称相同而继续修改。

## 文件验证

- 解析 YPF 目录、原名字节、存储校验、范围、解压长度及脚本结构，拒绝越界或不支持格式。
- 按阶段核对目标 YBN 哈希和允许差异，保留其余命令、行号、控制地址及未修改资源。
- 汉化替换保留原 YPF 名称、目录顺序和旧数据区，追加新 payload，只更新对应记录。
- 对最终 ZIP 完整读回 CRC、大小、逐文件 SHA256，检查唯一成员、单一游戏顶层目录、UTF-8、ZIP64、无密码和无 EXE。
- 构建前后核对源文件指纹，独立输出并拒绝覆盖；失败不会覆盖旧交付。

`verify` 同时检查暂存目录和 ZIP 相对于本次 manifest 的完整性。它检测产物是否被改动，不替代手机运行，也不能凭与同一构建器一致证明算法正确。发布前另使用历史独立解析器、历史逐文件清单及合成负例核对公开工具。

## 压缩与历史哈希

本次复验包括 Windows Python 3.12.10 / zlib 1.3.1 和 Python 3.12.14 / zlib 1.3.2 的适用检查。稳定验收对象是最终展开脚本、游戏资源内容和允许变化范围。zlib 1.3.1 额外核对历史 BN/归档字节；其他版本的压缩流可以不同，必须记录本次新 hash。

新 ZIP 的时间戳、压缩流或元数据可能不同，不能把旧 ZIP 的整体 hash 作为新工具的跨环境唯一结果。使用 manifest 的成员集合、内容哈希和本次 ZIP 哈希判断完整性。

## 手机验收与隐私

新构建报告始终标记未由此次构建测试 iOS。历史用户反馈单列在案例文档，不能自动移植到新版本或全部场景。文件级、用户手机反馈和未覆盖范围分别记录。

仓库仅发布脱敏摘要：profile、工具/运行时版本、校验结果、资源数量和目标脚本 hash。完整游戏清单、展开资源、存档、截图、原始会话与模型日志只留在使用者本机，不作为贡献附件。
