# 《妖蛆之饵》咔咔喵兼容适配

本案例针对已支持的 YU-RIS 0.481 汉化版本和咔咔喵（KrkrCat）运行路径，历史测试环境为咔咔喵 1.5。公开工具 profile 为 `maggot-r1`。

## 汉化加载与启动兼容链

汉化资源封装在 `maggotbaits_cn.exe` 的 Enigma Virtual Box 文件树中，包含 198 个 YBN 和 498 张 PNG，共 696 个文件。按原虚拟路径外置资源后，文件检查通过，但用户在咔咔喵中仍看到日文。这说明“文件已展开”不足以证明该运行路径能优先加载它们。

最终流程包含以下前置处理：

1. **EVB 静态读取。** 验证文件树、边界、未压缩标志和资源指纹，不执行或重构 EXE。
2. **V2 五 YPF 合并。** 将 696 个资源替换到 BN、CG、CGSYS、update1、update2 的 699 个既有位置。三处跨包重复同步更新，不新增乱码名称，不转换汉化图片/剧情文本。
3. **V3 标题参数规范化。** V2 手机启动曾出现 `KrkrCat.EngineFailure 错误1`。中文 script28 的 PC61 / WINDOW.CAPTION 参数引用越过表达式段声明边界；将原 79 字节标题字符串搬到合法表达式区域，更新引用和区段长度，保持文字、命令和行号内容。
4. **V4 保存恢复兼容处理。** 在 script18 PC453 的既有 CG 指令增加 `E=0`，保留控制流和其他参数。此步骤为最终已测试包的基线组成部分，不独立宣称已确定其唯一作用。
5. **R1 透明终点处理。** 应用下述 script27 单点条件修改。

R1“只改一处”指相对 V4 的行为差异。相对原始源游戏，最终包已经包含上述完整链。工具直接从源目录生成必要阶段资源及最终 ZIP，不要求已有 V4 游戏包。

## R1 的证据与修改

异常存档读档后出现黑屏或立绘消失，推进到后续场景才可能恢复。正常的 6 号存档具有与异常样本相同的部分相关保存标量，因此不能将这些值直接当作唯一根因。

修改 `ysbin/yst00027.ybn` 的零基 PC5312 条件：

```text
旧：@2838[@3525] == 0
新：(@2838[@3525] == 0) OR (@3525 == @3052 AND @3548 == 0)
```

保留 PC5313：`@3546 = @3546 * @3548 / 256`。只让非链接 FD 遮罩在透明终点取得普通透明度零，保留中间进度、其他图层、链接分支、TID/T/TA 和每次绘制重新计算的行为。

追加 57 字节条件，原 descriptor `(0,1,23,112706)` 改为 `(0,1,57,137569)`；保留 6,565 条命令、1,870 个控制描述符、原行号与 END。三个 update 包无 `ysbin/` 条目，不覆盖目标脚本。

最终工具保留源包六个系统保存文件 `config/extra/global/kidoku/seld/voice.sd`，不加入另行提供的手机存档。汉化配置与原 `.dat`、必要 DLL 保留；DLL 只复制，不执行。

## 已确认的手机结果

2026-10-14 用户明确确认：**1、2、6、7 号存档直接读档和退出重开后读档均正常，背景与应有立绘无需推进剧情即可恢复**；健康 6 号对照保持正常。维护者没有直接操作手机。

每档三次、全部剧情/转场模式及“新建存档→退出重开→读档”未完整逐项确认，不扩展为全游戏验收。旧交付说明中的“待验收”是发布包时的状态，本案例纳入了之后的独立用户反馈。

## 复验步骤

1. 使用 `maggot-r1` 构建新目录和 ZIP，独立导入咔咔喵，保留旧条目。
2. 先不导入个人存档，检查启动、中文菜单、新游戏和正常淡入淡出。
3. 需要回归时由使用者自行导入自己的匹配存档，按 1、6、2、7 的顺序观察；读档后先不要推进剧情，各重复三次。
4. 退出重开再读上述存档，并检查正常剧情推进和新建存档流程。

通过标准为画面立即恢复，健康对照不回归，正常转场与存读档保持。有限语义模型和资源校验通过不代替这些手机步骤。
